# Swarma Router

This skill candidate covers two distinct interfaces. It is not installed or released.

For the implemented `queued-task-handoff/0.1.0` MVP, read [queued notice usage](references/queued-task-handoff.md). It accepts explicit plan/dispatch requests and a private local policy, posts a task notice and retains its verified receipt. Use a supplied reviewed artifact and an admitted tuple; this draft does not install a command or authorize a post. The MVP does not choose a worker/model, resolve liveness, launch, claim or change an assignment.

For the **proposed full** `swarma-router/0.1.0` interface draft 4, prepare and inspect documents only. Its Route/Recommend/Explain/Apply/Status transport, selector, plugins and conformance runner remain pending implementation and admission. Do not send those operation envelopes to the MVP or invent a CLI, terminal-input route, native launch, direct board write or private counterpart import.

Read [the design manager guide](references/managers.md) for proposed routing, recommendation, explicit Apply, Explain or recovery; [the plugin guide](references/plugins.md) for proposed adapter declarations, static selection and qualification; and [the design conformance guide](references/conformance.md) for scenario specifications. These design-only guides point to the exact schemas in [the accepted interface design](references/interface-contract.md), the normative source for full-interface field names, union variants, budgets, capability IDs and action ordering. They do not extend the MVP schema or claim its native adapters implement the full ports.

The bundled contract is exactly 128324 bytes/415 lines, SHA-256 `57b1d2883288b793e088dc16437ab9aa96b8dd726d1dcae79339113e18e33d65`. Design acceptance establishes documentation readiness only. Any future released interface needs its own version/identity, supported entry point and qualification; do not silently transfer this draft's verdict.

In the full design, use Route for ordinary task-to-card-member delivery; the router resolves liveness. Recommend is pure selection over complete frozen input. Explain returns an authorized stored decision and its exact input. Apply is a separately authorized stored switch, restricted here to same-member/same-slot/owner/placement replacement. Status reconciles an existing effectful operation; it does not retry it.

For either interface, distinguish source evidence, effect authority and execution outcome. A valid pin, digest, observation, profile, recommendation or read permission grants none of the others. Use only the MVP request/policy fields in its guide. For a full-design request, unknown liveness cannot become stopped and unknown quota/resources cannot become spare capacity; preserve exact caller/project/task/card/generation and owner restrictions.

For the MVP return its actual status, correlation and any event ID with the limits in its guide; preserve its journal on uncertainty. For a full-design request return the proposed operation and complete required input references, evidence still missing, expected valid and forbidden outcomes, and actual verification limits. For partial or uncertain full-design effects preserve the same operation/correlation/claim and specify same-owner Status reconciliation. Never present queued delivery as task completion, next_check as an armed timer, a fixture as live qualification or an accepted design as an installed skill.
